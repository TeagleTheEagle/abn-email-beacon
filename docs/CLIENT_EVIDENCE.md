# Evidence required for real project cards

Do not publish a client card, quote or outcome until the relevant evidence is supplied and approved.

For each project, obtain:

1. **Identity and permission:** Client's approved public business name, destination URL, and written permission to show the project and any named person/testimonial.
2. **Problem:** A short client-approved description of the situation before the work. No invented conversion or revenue problem.
3. **Delivered work:** Actual scope supplied by Teague Industries, with delivery date and whether it was a demo, internal project or paid client build.
4. **Screenshots:** Current approved desktop and mobile screenshots, with private/customer information removed and alt text supplied.
5. **Outcomes:** Only verified measurements with source, measurement window and comparison baseline. If there is no measurement, describe the delivered work without a numeric result.
6. **Testimonial:** Exact approved wording, attribution and permission. Otherwise omit the testimonial entirely.
7. **Ongoing accuracy:** Review date and a note to remove/update the card if the site changes substantially.

The current `src/content/projects.ts` already labels fictional demos as Demo and the Teague template store as an internal live project. No empty evidence cards should be rendered.
